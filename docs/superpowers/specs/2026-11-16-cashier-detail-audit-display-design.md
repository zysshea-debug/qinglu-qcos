# 流水详情核对信息展示设计

**日期：** 2026-11-16  
**范围：** 收银流水页的“详情”弹窗

## 问题

结算页已经保存应收、实收、差额和备注，但“流水详情”仍使用旧的玩家 `grand_total` 字段作为“实收”显示，且未读取整桌结算记录。整桌结账时该字段会被置为零以防营业额重复统计，导致详情页无法用于核对。

## 目标

让流水详情成为结账后的核对凭据：操作员打开任意桌局，都能直接看清应收、实收、差额和备注，并能区分逐人结账与整桌结账。

## 展示规则

### 整桌结账

详情顶部增加“本桌结算核对”区，唯一以 `table_settlements` 记录作为金额事实，展示：

- 结算方式：整桌结账；
- 约定整桌台费；
- 商品合计；
- 应收；
- 实收；
- 差额；
- 备注；
- 付款人、支付方式、操作人和结算时间。

玩家表改为解释性明细，只显示玩家、时长、计算台费、个人商品和“由整桌结算”状态；不得将玩家 `grand_total` 作为该玩家或该桌的实收展示。

### 逐人结账

玩家表直接增加并显示：应收、实收、差额、备注和支付方式。金额来自该玩家结账时保存的 `grand_total`、`actual_amount`、`difference` 和 `note`。

旧记录没有实收字段时，以原有应收作为兼容显示，并明确标为历史记录，不能伪造备注或差额。

### 共同规则

- 差额为零时显示 `¥0.00`；无备注显示“无”。
- 商品明细继续显示实际商品记录，不改变归属、金额或结算状态。
- 详情接口一次返回必要的整桌结算记录或逐人字段；前端只负责展示，不重新计算金额。

## 数据与安全

- 不修改既有结算记录，不新增或回填历史金额。
- 只读查询 `table_settlements`，按 `session_id` 取该桌唯一记录。
- 保留现有角色权限：仅有收银流水查看权限的人员可打开详情。
- 金额来源仅限已保存的数据库字段，禁止依据前端传值或玩家明细推算整桌实收。

## 验收场景

1. 逐人结账有差额和备注时，详情中该玩家能同时看到应收、实收、差额和备注。
2. 逐人结账无差额时，详情显示差额 `¥0.00`、备注“无”。
3. 整桌结账详情顶部显示约定台费、商品、应收、实收、差额、备注和付款人。
4. 整桌玩家行显示“由整桌结算”，不再显示零元或分摊后的假实收。
5. 商品明细仍与原记录一致。
6. 历史记录仍可打开，且不因缺少新增字段而报错。
