# 整桌结账与结算备注设计

**日期：** 2026-11-15  
**范围：** 青鹭 QCOS 的现有结算流程

## 目标

在不改变现有逐人结账和折扣能力的前提下，新增整桌结账，并让每一笔应收与实收不一致的结算都有可追溯的备注。

## 明确不做的内容

- 不增加“公开包桌”“协议包桌”或其他新的收费分类。
- 不改变当前逐人结账可选择折扣的逻辑。
- 不将饮料、零食等商品并入谈好的整桌台费。
- 不改写既有历史流水。

## 结算方式

### 逐人结账（保持现状，补充备注）

现有流程与可选折扣保持不变。每位玩家仍按其台费与本人商品结账。

结算界面增加“备注”输入框：

- 最终实收等于应收时，备注可留空；
- 最终实收不等于应收时，备注必填；
- 后端同样校验此规则，不能只依赖界面提示。

### 整桌结账（新增）

在台桌结算区与现有逐人结账并列新增“整桌结账”入口，仅用于已谈好整桌台费的情况。

操作员输入该桌谈好的**整桌台费**后，系统自动计算：

```
应收 = 整桌约定台费 + 本桌全部未结商品合计
```

商品仍按实际销售金额计入，不受谈好台费影响。商品原先归属到哪位玩家的明细继续保留，只是在这次整桌结账中由整桌付款人一并付清。

例如：约定整桌台费 ¥300，全桌未结商品 ¥86，则应收 ¥386。

操作员随后录入实收、支付方式和备注；实收与应收不一致时备注必填。

## 数据保存与展示

每次整桌结账保存以下不可变的结算事实：

- 结算范围：整桌；
- 约定整桌台费；
- 商品合计；
- 最终应收、实际收款及差额；
- 支付方式、备注、操作人和结算时间；
- 所属桌局编号。

玩家的台费计算、开始/结束时间和商品归属不丢失。整桌结账完成后，玩家显示为“已由整桌结算”，而不是把同一笔实收平均写入每个人，以免日报与营业额重复计算。

流水详情、日报和导出表须显示整桌结算的约定台费、商品合计、应收、实收、差额与备注；营业额只计入一次整桌实收。

## 一致性与异常处理

- 仅汇总当前仍未结算的玩家台费和商品；已单独结账的项目不能再次计入整桌。
- 整桌结算在一个数据库事务中完成：写入结算记录、更新全体未结玩家状态、结清全桌未结商品并关闭桌局。任一步失败则全部回滚。
- 已关闭、已完全结清或不存在的桌局不能再次整桌结账。
- 扫码支付若启用支付确认，确认金额必须等于本次填写的实际收款；当实际收款与应收有差额时，仍要求备注说明。
- 会员支付仅在满足现有会员归属与余额校验时可用；整桌结账的会员付款沿用现有安全校验，不允许绕过。

## 验收场景

1. 逐人结账：应收与实收相同，可不填备注。
2. 逐人结账：应收与实收不同，空备注被拒绝；填写备注后成功。
3. 整桌结账：约定台费 + 全桌未结商品正确汇总；只产生一笔营业额。
4. 整桌结账：实收差额无备注被拒绝；有备注后成功，流水可见。
5. 整桌结账后，所有未结玩家与商品均为已结算，重复结算被拒绝。
6. 已有逐人结账与历史记录的显示、统计和导出不发生变化。
